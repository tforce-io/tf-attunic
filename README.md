# TFattunic

[Copier](https://copier.readthedocs.io/) template attuned to multi-language and multi-framework support for any project. See [Appendix](#supported-languages) for details.

This `README.md` is for the template itself; it won't be copied into downstream projects.

## Install

Generate a new project:

```sh
copier copy gh:tforce-io/tf-attunic .
```

Then fill in `.attunic/context.md`; the template is ready to use.

Update an existing project that was generated from this template:

```sh
copier update
```

If an update asks a question you have never answered before, answer it; the new answer is stored in `.copier-answers.yml` for future updates.

`copier update` resolves template versions from [PEP 440](https://peps.python.org/pep-0440/)-compliant Git tags on this repository (e.g. `v1.0.0`). A safe downstream update requires all of these:

1. The project has a committed `.copier-answers.yml` (generated by this template; never edited manually).
2. The project is a Git repository with a clean `git status`.
3. The template change being propagated is reachable via a tag. `copier update` uses the latest tag by default; untagged refs require `--vcs-ref=HEAD` and are only for temporary testing, never for updating released projects.

## Customize

To customize the generated files to follow your project, add your rules below the `<!-- Project-specific -->` or `<!-- Project-specific / <Section> -->` marker of the section you are overriding. Project-specific rules supplement the template rules; when they conflict, the project-specific rules take precedence.

- Each section in a template-owned file ends with one `<!-- Project-specific -->` or `<!-- Project-specific / <Section> -->` marker, uniquely named after the section. In `.editorconfig` / `.gitignore` it is a plain `# Project-specific` comment. Everything above a marker is template-owned; everything below it is project-owned. For general additions, use the final `Project-specific` section's marker.
- **DO NOT** add, edit, or delete anything above a marker, and never move or duplicate a marker.
- **DO NOT** edit `.copier-answers.yml`; Copier maintains it and relies on it to replay your previous answers on `copier update`.

## Questions

| Question            | Description                                               |
|---------------------|-----------------------------------------------------------|
| `project_name`      | Name of the generated project                             |
| `languages`         | Language(s) of the project; multi-select                  |
| `frameworks`        | Framework(s) of the project; multi-select; shown only when a selected language has supported frameworks |
| `license`           | Open source license (see [Appendix](#supported-licenses)) or `None` |
| `copyright_holder`  | Copyright holder name (skipped if `license` is `None`)    |
| `copyright_year`    | Copyright year (skipped if `license` is `None`)           |
| `license_header`    | License header style for code files: `Full`, `SPDX`, or `None` (skipped if `license` is `None`) |

## Template Layout

```
├── .agents/                   # shared AI agent instructions copied into generated projects
├── .attunic/                  # project memory (see Project Memory section below)
├── frameworks/<framework>/    # framework-specific content, included by the root templates above, one folder per supported framework (not copied)
├── languages/<language>/      # language-specific content, included by the root templates above, one folder per supported language (not copied)
├── licenses/                  # license text fragments, license notice fragments, included by LICENSE.jinja / COPYING*.jinja / .agents/license-header.md.jinja (not copied)
├── .copier-answers.yml.jinja  # emits .copier-answers.yml (required by copier update)
├── .editorconfig.jinja        # generic editor formatting rules + language fragment included before the Project-specific marker
├── .gitignore.jinja           # generic ignore rules + language fragment included before the Project-specific marker
├── AGENTS.md                  # agents' entry point of this repo itself; maintained manually, not copied
├── AGENTS.md.jinja            # entry point for AI agents in generated projects
├── CLAUDE.md                  # this repo's pointer to AGENTS.md; not copied
├── CLAUDE.md.jinja            # renders CLAUDE.md, which points to AGENTS.md
├── COPYING.jinja              # renders COPYING for GPL-3.0-only, GPL-3.0-or-later, the GPL part of LGPL-3.0-only / LGPL-3.0-or-later, AGPL-3.0-only, AGPL-3.0-or-later
├── COPYING.LESSER.jinja       # renders COPYING.LESSER with the LGPL text (LGPL-3.0-only and LGPL-3.0-or-later)
├── LICENSE                    # MIT License Text for this template (not copied)
├── LICENSE.jinja              # renders LICENSE for LICENSE-based licenses (MIT, ISC, BSD-2-Clause, BSD-3-Clause, 0BSD, Apache-2.0, MPL-2.0)
├── README.md                  # template documentation; not copied
└── copier.yml                 # template questions and settings
```

### Project Memory (`.attunic/`)

Generated projects carry a markdown-only project memory in `.attunic/`, adapted from [clean-code-skills](https://github.com/btseee/clean-code-skills)' memory protocol. It lets a new agent session resume instead of guessing, with no scripts and no runtime tooling:

| File         | Created by                                                               |
|--------------|--------------------------------------------------------------------------|
| `context.md` | Pre-seeded by this template                                              |
| `memory.md`  | Pre-seeded by this template; append-only log of exceptions and deferrals |
| `wip.md`     | On demand, when an audit or cleanup campaign starts; gitignored          |

### Language Fragments (`languages/<lang>/`)

| Fragment                         | Included by                              |
|----------------------------------|------------------------------------------|
| `.editorconfig.jinja`            | `.editorconfig.jinja`                    |
| `.gitignore.jinja`               | `.gitignore.jinja`                       |
| `coding-conventions.md.jinja`    | `.agents/coding-conventions.md.jinja`    |
| `development-guideline.md.jinja` | `.agents/development-guideline.md.jinja` |
| `project-structure.md.jinja`     | `.agents/project-structure.md.jinja`     |

Shared/general sections live in the root templates; each root template `{% include %}`s the language fragment of every language selected in the multi-select `languages` answer (in the question's choices order). These fragments are never emitted as project files.

TypeScript inherits JavaScript's rules: when `typescript` is selected without `javascript`, the `.gitignore.jinja`, `coding-conventions.md.jinja`, and `development-guideline.md.jinja` fragments of `javascript` are included right before the TypeScript ones; the `typescript` fragments hold only what TypeScript adds or overrides, and state that their rules win where the two conflict.

### Framework Fragments (`frameworks/<framework>/`)

| Fragment                         | Included by                              |
|----------------------------------|------------------------------------------|
| `coding-conventions.md.jinja`    | `.agents/coding-conventions.md.jinja`    |
| `development-guideline.md.jinja` | `.agents/development-guideline.md.jinja` |
| `project-structure.md.jinja`     | `.agents/project-structure.md.jinja`     |

Each root template `{% include %}`s the framework fragment of every framework selected in the multi-select `frameworks` answer (in the question's choices order), right after the language fragments. These fragments are never emitted as project files.

## Maintain the Template

- Keep the marker convention from the [Customize](#customize) section above in every new Markdown template, including the fragments in `languages/<lang>/` and `frameworks/<framework>/`; files without sections, such as the license renderers, take none (see `AGENTS.md`'s Coding Conventions).
- Keep the marker text byte-identical across versions; Copier matches on this line as diff context, so even a whitespace or punctuation change can break the anchor and produce spurious conflicts.
- Only make changes to content above the `<!-- Project-specific -->`, `<!-- Project-specific / ... -->`, or `# Project-specific` marker in each section.
- To add a new language, create `languages/<lang_code>/` with all the fragments listed above and add `<lang_code>` to the `languages` question's choices (an array multiselect) in `copier.yml`; declare its owner-defined indentation in its `.editorconfig.jinja` and list it under [Indentation](#indentation); add its line-comment token to `line_comment_tokens` in `.agents/license-header.md.jinja` if it has line comments; and add the code to [Supported Languages](#supported-languages) and to the language lists in `AGENTS.md`'s Technical Specifications and Naming Conventions.
- To add a new framework, create `frameworks/<framework_code>/` with all the fragments listed above and add `<framework_code>` under each supported language block in the `frameworks` question's dynamic choices in `copier.yml` (a framework supporting several languages is listed under each of them; for a language without frameworks yet, also extend the question's `when` condition and its choices, which are an `if`/`elif` chain today); then add the code to [Supported Frameworks](#supported-frameworks) and to the framework lists in `AGENTS.md`'s Technical Specifications and Naming Conventions.
- To add a new license, update `copier.yml` (choices, `_exclude` branches), create the `licenses/<id>.jinja` and `licenses/<id>-notice.jinja` fragments, update the `LICENSE.jinja` / `COPYING.jinja` includes, and update the README's License File Mapping table and Supported Licenses list, the license list in `AGENTS.md`'s Technical Specifications, and the license names in the `LICENSE.jinja` / `COPYING.jinja` Layout comments of both `AGENTS.md` and this README, in the same commit.
- Never move or re-point a published tag (no force-push to tags); ship corrections as a new tag instead.

### Indentation

Reference for `.editorconfig`: every `indent_style` or `indent_size` a language or format owner defines is declared explicitly; Markdown is declared with spaces by this template's choice, matching the Markdown it generates; everything else falls back to the `[*]` default (`indent_style = tab`, `indent_size = 2`), a proposal of this template.

| Files | `indent_style` | `indent_size` | Defined by |
|-------|----------------|---------------|------------|
| Go: `*.go`, `go.mod`, `go.work` | `tab` | `2` (default) | [gofmt](https://pkg.go.dev/cmd/gofmt), [`go mod edit -fmt`](https://go.dev/ref/mod#go-mod-edit), [`go work edit -fmt`](https://go.dev/ref/mod#go-work-edit) |
| Make: `Makefile`, `makefile`, `GNUmakefile`, `*.mk` | `tab` | `2` (default) | [GNU make recipe syntax](https://www.gnu.org/software/make/manual/html_node/Recipe-Syntax.html) |
| Markdown: `*.md` | `space` | `2` (default) | This template: generated Markdown nests lists with spaces |
| PowerShell: `*.ps1`, `*.psd1`, `*.psm1` | `space` | `4` | [PSScriptAnalyzer UseConsistentIndentation](https://learn.microsoft.com/en-us/powershell/utility-modules/psscriptanalyzer/rules/useconsistentindentation) |
| Python: `*.py`, `*.pyi` | `space` | `4` | [PEP 8](https://peps.python.org/pep-0008/#indentation) |
| Rust: `*.rs` | `space` | `4` | [Rust Style Guide](https://doc.rust-lang.org/style-guide/#indentation-and-line-width) |
| YAML: `*.yaml`, `*.yml` | `space` | `2` (default) | [YAML 1.2.2, 6.1 Indentation Spaces](https://yaml.org/spec/1.2.2/#61-indentation-spaces) |
| Everything else, e.g. JavaScript, TypeScript, Shell, Text, JSON, TOML | `tab` (default) | `2` (default) | No owner rule |
